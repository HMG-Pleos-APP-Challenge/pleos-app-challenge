# 유 담당 2차 구현 검토안 — 도로 기반 셀 해금

상태: 2차 구현 및 아래 범위의 검증 완료 / 사용자 검토 전 / 2차 커밋 전.
1차 승인 커밋: `c0383b1` — 남양읍 최초 발견 판정과 개인 도감 저장 구현.

## 범위와 선택

사용자가 1차 로컬 커밋 및 2차 구현을 승인했다. 2차도 동작 확인 → 사용자 검토 → 승인 후 로컬 커밋 순서를 유지한다. 이번에는 랜드마크/서버/공통 XP를 구현하지 않는다.

기본 해금 단위는 **자동차용 도로가 있는 100m 셀**이다. 단순히 GPS 주변 원/이웃 셀 전체를 열지 않고 관측된 셀 하나만 판정한다. 통과 사이의 미관측 셀을 보간해서 해금하지 않는다. 도로 세그먼트를 정확히 특정하는 map matching이나 팀 점령 이벤트를 생성하지 않는다.

`exploredUnitCount = 개인 해금 셀 수`, `totalExplorableUnitCount = 해당 버전의 대상 셀 수`로 동일 단위를 사용한다. 현재 분모는 **1,579개**이다. `unlockedRoadCount`에 셀 수를 넣지 않고 0을 유지한다. 이 탐험률은 수집된 공개 도로 기반 테스트 카탈로그 기준이며 전국 면적/남양읍의 모든 실제 도로를 분모로 삼지 않는다.

## 실제 데이터

- [OpenStreetMap 라이선스](https://www.openstreetmap.org/copyright): © OpenStreetMap contributors, ODbL 1.0.
- [Geofabrik 한국 배포 페이지](https://download.geofabrik.de/asia/south-korea.html)의 `south-korea-261108.osm.pbf`, MD5를 배포자의 체크섬과 대조했다.
- 남양읍과 교차하는 차량용 공개 도로 원본 **643개**, 경계 안쪽으로 자른 폴리라인 **612개**.
- 선택 highway: motorway/trunk/primary/secondary/tertiary 및 각 link, unclassified/residential.
- 제외: area=yes, tunnel=yes/building_passage, access/vehicle/motor_vehicle/motorcar 값이 no/private/agricultural/forestry/destination/delivery/customers/permit인 도로, 해당 조건부 통행 태그가 있는 도로. service/track/footway/cycleway/path/construction은 대상 종류에 포함하지 않는다.
- 카탈로그 버전: `osm-geofabrik-20261108-namyang-grid100-v1`. 출처·라이선스·체크섬은 [도로 데이터 고지](data/ROAD-DATA-NOTICE.md)에 보존한다.
- 도로 원본 부분집합은 `docs/data/namyang-osm-roads.geojson`, 런타임 카탈로그는 `app/src/main/assets/exploration/namyang.roadcells`이다. 이 데이터베이스와 생성 방법을 ODbL로 함께 제공한다. 개인 해금 파일/원본 위치는 데이터 배포본에 포함하지 않는다.

이번 데이터는 로그인·API 키 없이 공개 파일로 확보했다. ITS 공식 파일도 확인했으나 이번 앱 번들에는 사용하지 않았다. 실시간 조회 서버의 가용성에 앱이 의존하지 않도록 날짜 고정 배포본을 전처리했다. OSM 접근 속성의 누락·변경 가능성이 있으므로 실제 운행 가능성을 보증하는 내비게이션/통행 안내로 사용하지 않는다.

## 카탈로그 생성

기존 SGIS 남양읍 Polygon/MultiPolygon에서 25m 안쪽 영역과 도로선을 교차시킨다. 위경도를 미터로 착각하지 않도록 위도 37.2/경도 126.8을 원점으로 하는 고정 지역 평면 좌표를 사용한다. x는 경도차 × 지구 반지름 × cos(37.2°), y는 위도차 × 지구 반지름이며 모두 라디안으로 변환한다. 남양읍 테스트 범위용 근사이며 전국 투영으로 확장하지 않는다.

100m 셀의 사방 10m를 제외한 안쪽에 도로가 20m 이상 있는 셀만 분모에 포함한다. 경계와 접하기만 하는 셀/짧은 조각을 제외해 GPS로 확인하기 어려운 분모를 줄인다. 카탈로그는 버전/지역 ID/격자 정의/원본 도로 ID 및 좌표/셀별 도로 인덱스/모의 경로를 가진다. 셀 ID는 카탈로그 버전 + 열/행이다. 지도 셀과 점령 도로 ID를 혼용하지 않는다.

재현: `python -m pip install -r tools/geo-requirements.txt` 후 `python tools/build_road_cells.py --boundary app/src/main/assets/exploration/namyang.boundary --roads docs/data/namyang-osm-roads.geojson --output <출력경로>`.
전체 PBF부터 다시 추출하려면 동일 명령에 `--pbf <원본경로>`를 추가한다. 공간 도구는 개발용 전처리 도구이며 Android 앱에 추가된 라이브러리가 아니다.

## 판정 조건

1. 기존 공통 LocationSample을 전달받는다. MOCK과 PLEOS를 혼합하지 않는다. 실제 SDK 구독/권한 요청은 추가하지 않았다.
2. 좌표·ID·UTC timestamp가 유효하고 정확도는 확인된 25m 이하이어야 한다.
3. 위치 오차 반경이 남양읍 경계나 셀 경계와 겹치면 해금하지 않는다.
4. 현재 셀이 카탈로그에 있고, 해당 셀의 도로와 거리 + 위치 정확도 ≤ 30m이어야 한다.
5. 같은 셀에서 서로 다른 위치 이벤트가 3초 이상 확인되며, 최초 확인 위치에서 8m 이상 이동해야 한다. 이전 샘플과 간격은 30초 이하이다.
6. 30초 이하의 연속 입력에서 60m/s를 초과하는 위치 점프는 거절하고 확인을 다시 시작한다. 이는 게임 보상 조건이 아닌 오류 차단 상한이다.
7. 사용자+카탈로그 셀당 최초 해금만 저장한다. 이미 발견한 지역 도감이 열린 경우에만 셀 결과를 저장한다.

위치는 도로 근처 이동을 보여줄 뿐 실제 차량 운행을 증명하지 않는다. 실제 차량 상태/실차 위치 연동은 후속 기술 검증이다. 구름·터널·오래된 도로 자료 등으로 실제 주행을 놓칠 수 있으며, 미확인 구간을 임의로 해금하는 방식으로 보정하지 않는다. 수치들은 담당 로직의 검토 가능한 초기 설정이다.

## 저장·호환성

- 1차 `mock-discoveries.bin`을 그대로 읽고 보존한다. 이를 셀 저장 형식으로 덮어쓰지 않는다.
- 2차는 `mock-cells.bin`에 사용자/버전 포함 셀 ID/최초 해금 UTC/source만 저장한다. 위치 원본·미확정 후보·경로는 저장하지 않는다.
- 셀 파일도 같은 폴더의 임시 파일 쓰기·동기화·원자적 교체 후에만 결과를 발표한다. 실패하면 판정 임시 상태를 되돌려 같은 입력 재시도가 가능하다.
- 지역 발견과 셀 해금 파일은 두 개이므로 전역 단일 트랜잭션은 아니다. 셀 저장이 실패해도 유효한 지역 발견이 먼저 저장될 수 있다. 셀 해금을 성공으로 발표하지 않고 재시도하여 복구한다. 관련 회귀 시험을 둔다. 셀/XP 원장을 확장할 때 Room 트랜잭션으로 합치는 것이 권장된다.
- 버전 불일치·손상·카탈로그에 없는 셀은 오류로 표시하고 기존 파일을 지우지 않는다. 다음 데이터 버전 전환에는 별도 마이그레이션이 필요하다.
- Summary의 `lastUpdatedUtcMs`는 지역 최초 발견과 최근 셀 해금 중 최신 시각이다. 따라서 프로필 표시를 ‘최초 발견’에서 ‘최근 탐험’으로 바꿨다. 실제 최초 발견 시각은 기존 발견 데이터에 보존한다.

## 화면·공통 영향

개인 지도에 실제 지역 경계, 도로선, 회색 대상 셀/초록 해금 셀을 그린다. 배경지도 SDK나 실제 GPS가 아니며 모의 입력임을 표시한다. ‘도로 이동 재생’은 같은 실제 원본 도로 `osm:way:1049267064:v1:p0`에서 이어지는 4개 셀의 관측점 8개를 시간 순으로 재생한다. 길찾기 경로 안내가 아니다. 반복 재생은 새 해금 0개가 되어야 한다.

프로필과 홈은 기존 Summary를 사용한다. 프로필에 셀 수/탐험률을 표시하고, 셀 수와 해금 도로 수를 구분한다. 이번에는 MainActivity·core·navigation·Gradle·Manifest·최 담당 화면을 변경하지 않는다. 공통 모델/호출 계약은 그대로다. 바뀐 탐험률 단위와 최근 탐험 시각 의미는 통합 시 상대에게 공유해야 한다. 공통 계약의 공동 승인 상태를 임의로 변경하지 않는다.

## 완료 기준과 검증 기록

코드 생성만으로 검증 완료를 표시하지 않는다. 기존 1차 테스트 + 도로 셀 판정/도로 밖/오차/시간 역행/사용자 분리/중복/위치 점프/재시작/저장 실패/1차 파일 보존/실제 데이터 입력 시험, Lint와 APK 빌드를 실행한다. 에뮬레이터는 1차 설치 위에 업데이트하여 발견 기록 유지와 4셀 해금·재진입·재시작 복원을 확인한다.

2026-11-09 실행 결과:

- `testDebugUnitTest lintDebug assembleDebug` 성공. 테스트 36개(1차 16 + 2차 17 + 기존 통합 3), 실패 0 / 오류 0.
- Lint 오류 0, 기존 공통 설정 경고 4(라이브러리 버전 안내 2, 백업 규칙, 앱 아이콘) 유지. 새 앱 의존성/DB/SDK를 추가하지 않았다.
- 동일 로컬 도로 추출본으로 카탈로그 재생성 후 SHA-256 일치 확인. PBF의 MD5도 제공자 체크섬과 일치했다.
- `git diff --check` 통과. 2차는 아직 로컬 커밋하지 않았다.

Pleos Connect 2.1.0 / API 34에서 1차 설치 위에 2차 APK 업데이트:

1. 기존 발견 지역 1개 유지, 신규 셀 0 / 1,579개, 탐험률 0.0%로 시작.
2. 도로 이동 재생 시 4 / 1,579개 해금, 탐험률 0.3%, 지도와 프로필에 동일 값 반영.
3. 동일 경로 재생 시 새 해금 없음, 기존 셀 4개 및 최근 탐험 시각 유지.
4. 앱 프로세스 종료 후 재실행해 프로필의 4 / 1,579개·0.3%·최근 탐험 시각 복원 확인.
5. 기존 발견 파일의 SHA-256이 업데이트 전후 및 셀 해금 후에도 동일: `6ece6aa246e8879f39f821a906c6aa44e26a2cfa603cc5c471fe66d47b09893c`.
6. 셀 파일의 재시작 전후 SHA-256 동일: `63548860201055545cc0fed5390390029c9e6a581e804ef7a76306ea5baf7de0`.
7. 앱 패키지의 crash 로그 일치 항목 없음. 다른 Pleos 시스템 서비스의 오류를 앱 성공/실패 판정에 혼합하지 않았다.

실제 GPS·차량 상태·백그라운드 위치·실주행 map matching·랜드마크·XP·서버 동기화는 구현/검증 완료로 표시하지 않는다. 시연은 실제 공개 도로 형상 위의 모의 위치 입력이다.

커밋 후보: `남양읍 도로 기반 셀 해금과 탐험률 저장 구현`. 사용자 검토 승인 전 2차 커밋·push·PR·원격 병합은 수행하지 않는다.
