# 점령·홈 전체 검토와 탐험 호환성 검토

2026-11-11 검토 기준은 choi 8a9586e, origin/main 35e576a, 상대 브랜치 1cc7543이다. fetch 후 추가 원격 변경이 없었다. 점령의 도메인·파일·세션·시연·지도·홈과 관련 테스트를 읽고, MainActivity, 탐험 세션·위치 어댑터·추적 서비스·차량 상태·인증·큐·프로필 연결을 추적했다. Notion 공통 계약 재조회 결과는 공동 승인 대기다.

## 우선 수정할 사항

아래는 소스 경로를 추적해 확인한 결함과 재현 조건이다. 이번 검토에서 새 기기 오류 주입 시험은 수행하지 않았다. P1은 기록 보존에 우선 대응할 항목, P2는 특정 조건에서 기능·표시가 잘못되는 항목이다.

### P1 완료 이벤트의 저장 실패 후 프로세스 종료 시 유실

ConquestLocationPipeline.kt 15, 29~42행은 완료 이벤트를 ArrayDeque에 넣고 파일 저장 실패 때 메모리에 남긴다. 실패 후 앱 프로세스가 종료되면 이벤트가 사라진다. 기존 재시도 테스트는 같은 객체에서 다음 샘플로 재시도하는 경우를 검증한다. 재시작 복구는 포함하지 않는다. 성공적으로 파일에 저장된 기존 기여 복구와 구별해야 한다.

대응은 점령 전용 영속 완료 큐다. 저장 성공 전후 장애와 ACK 전후 장애를 각각 시험한다. 서버 검증을 계획한 만큼 RoadVisited만 저장하는 설계에 그치지 않고 완료 구간의 검증 근거를 보존할 구조도 함께 정한다. 디스크 자체가 기록을 거부한 경우에는 오류를 유지하고 미저장 상태를 사용자에게 알린다.

### P2 SDK에서 허용한 미래 시각이 점령에서 조용히 폐기됨

PleosLocationSource.kt는 수신 시각보다 최대 5초 앞선 SDK 시각을 허용한다. ContributionLedger.kt 50행은 점령 처리 시각보다 조금이라도 미래인 완료 이벤트를 FUTURE로 반환한다. ConquestLocationPipeline.kt 31~33행은 이 결과도 큐에서 제거하고 ConquestSession.kt 82행은 반환 목록을 소비하지 않는다. 따라서 출구 샘플이 허용 범위 내 미래이고 점령 처리가 그 시각 전에 끝나면 완주했어도 기여 0회이며 거부 사유도 보이지 않는다.

대응은 공통 원본 시각을 보존하면서 점령 내부에서 제한된 시간 대기·재시도 정책을 정하고, 최종 거부 사유를 점령 상태에 전달하는 것이다. 임의로 통과 시각을 현재 시각으로 바꾸면 12시 경계가 달라진다. +1초와 +5초, 낮 12시 직전/직후를 가짜 시계로 검증한다.

### P2 탐험 처리 오류가 같은 샘플의 점령 처리를 막음

ExplorationTrackingService.kt 103~104행은 session.acceptSdk를 먼저 기다린 후 conquest.onSample을 호출한다. 탐험 파일 읽기·쓰기 또는 요약 처리에서 예외가 전파되면 바깥 catch에서 서비스가 중지되고 해당 점령 입력까지 누락된다. 점령 세션 열기 실패도 80행에서 null로 처리돼 서비스 상태가 점령 실패 원인을 전달하지 않는다.

대응은 공통 배포부에서 기능별 오류 상태를 분리하고 각 기능의 입력 순서를 보존하는 것이다. Coroutine 취소는 전파한다. 탐험 내부를 점령에서 수정하는 대신 상대와 서비스 배포 지점의 최소 변경을 공유한다. 한쪽 저장소 오류를 주입해 다른 쪽 처리 지속 여부와 오류 표시를 시험한다.

### P2 점령 로딩 실패가 홈·프로필에서 정상 0으로 표시됨

MainActivity.kt 73행은 점령 상태가 없으면 0으로 채운 요약을 생성한다. 로딩 오류는 147행의 점령 화면 분기에서만 표시된다. 홈은 이를 기기 내 기록 0회·0구간으로 보여주고 프로필에도 같은 0 요약을 전달한다. 손상 파일이나 읽기 실패가 발생한 사용자는 기록이 사라진 것으로 이해할 수 있다.

대응은 ConquestSummary를 바꾸지 않고 화면 조립부와 홈에서 로딩/실패 상태를 별도로 전달·표시하는 것이다. 프로필 내부 대신 공통 조립부의 오류 안내를 우선 검토한다. 정상 빈 기록과 읽기 실패를 따로 시험한다.

### P2 기여 없는 점령 파일도 계정 복원을 차단함

SupabaseCloud.kt 102~104행은 SDK 점령 파일의 길이가 0보다 크면 복원을 막는다. LocalConquestFeature.kt 94~97행은 팀과 기여가 모두 비어 있어도 다음 낮 12시를 지난 조회에서 정산 시각을 파일에 기록한다. 따라서 기록 없이 앱을 켜 두었다가 정산 시각을 넘긴 새 기기도 복원 제한에 걸릴 수 있다. AccountSettings의 버튼 활성 조건은 이 점령 상태를 반영하지 않아 클릭 후 일반 실패 안내로 끝날 수 있다.

대응은 점령이 제공하는 계정 전환 가능 여부를 조립부에서 전달하는 경계다. 팀 선택·기여·미전송 기록·계정 매핑을 확인하고 단순 빈 상태는 허용하는 정책을 협의한다. 상대 인증 코드가 점령 바이너리 형식을 직접 읽게 만드는 방식은 피한다.

## 추가 한계와 개선 순서

- ConquestSession.change는 refresh 성공만으로 error를 지운다. 저장 실패로 완료 이벤트가 남아 있어도 30초 조회가 성공하면 오류가 사라질 수 있다. 큐의 미처리 상태와 일시 조회 오류를 따로 표시한다.
- 기존 고정 사용자 u-demo-01에서 설치 ID로 바뀌었으나 점령 이관은 없다. 이전 MOCK 팀 선택과 기여가 현재 사용자 요약에 나타나지 않는다. 기존 파일을 보존하면서 이관 또는 시연 기록 유지 정책을 결정한다.
- 특정 검증 Debug 에뮬레이터 외에는 정확도가 null이어서 점령을 인정하지 않는다. 실제 Pleos 정확도 계약 검증이 차량 기여 활성화의 선행 조건이다.
- 실제 다중 사용자 합산·서버 정산은 미구현이다. 로컬의 전체 기여 재검증과 과거 정산 재계산 비용은 기록 증가에 따라 커진다. 현재 6방향 규모 검증과 대규모 운영을 구별한다.
- 기본 Mock 시연은 기능별로 따로 실행된다. 점령 ConquestDemo와 탐험 replay는 각각 다른 입력을 사용한다. 동일 샘플로 양쪽이 동작하는 단위 테스트는 있지만 같은 시연 버튼으로 두 화면이 갱신되는 UI 흐름은 없다.

## 권장 작업 순서

1. 우리 영역에서 완료 처리 결과·미저장 상태를 명시하고 영속 큐 및 재시작 검증을 추가한다. 미래 시각 정책을 함께 정리한다.
2. MainActivity/서비스의 오류 배포, 홈 로딩·오류 표시를 최소 변경으로 공유한다. 저장 실패 주입 회귀를 추가한다.
3. 계정 복원 가능 여부와 인증 호출 경계를 상대와 합의한다. 서버 연결 설계는 이 결과를 반영한다.
4. 같은 남양읍 점령 경로를 양쪽 모의 세션에 배포하는 통합 시연을 구성한다. 고정 시각·ID와 저장 격리를 보장한다.
5. 서버 기여·정산과 실제 차량 검증, 도로 확대를 진행한다.

## 검증 범위

직전 통합 기준 35e576a에서 이 노트북의 테스트 122개·빌드·lint 및 일반 Android 시연이 통과했다. 이후 실행 코드 변경은 없다. 이번에는 소스·테스트·원격 차이 검토를 수행했으며 동일 빌드를 반복 실행하지 않았다. 발견한 예외 조건은 위 재현 절차를 자동 테스트로 추가한 뒤 수정 완료를 판정해야 한다. 이번 산출물은 검토 문서이며 실행 동작을 변경하지 않는다.
