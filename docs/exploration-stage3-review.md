# 유 담당 3차 구현 검토안 — 랜드마크 연속 체류 도감

상태: 3차 구현 및 아래 범위 검증 완료 / 사용자 검토·로컬 커밋 승인 완료.
승인된 기존 로컬 커밋: `c0383b1`(지역 최초 발견), `03fb999`(도로 셀 해금).

## 요청과 회의 근거

사용자가 2차 로컬 커밋 및 3차 구현을 요청했다. [11월 5일 최종 회의 정리](https://app.notion.com/p/11-5-40f99682f1f0800c8585c6274da5e64c)를 다시 읽었다. 회의에서는 랜드마크를 후속 확장으로 분류했고 정확한 체류 시간/반경은 정하지 않았다. 이번에는 사용자 요청으로 그 확장 기능을 구현한다. **100m / 120초 / 최대 관측 공백 15초**는 검토 가능한 초기 담당 설정으로, 공동 승인된 게임 규칙이라고 표시하지 않는다.

## 2차와의 관계

- 2차: 실제 이동 공간을 기록하는 도로 셀 해금과 탐험률이다.
- 3차: 명소별로 연속 체류가 관측되면 도감 카드를 한 번 얻는다.
- 같은 LocationSample을 두 기능이 소비할 수 있지만 판정·고유키·저장 파일·완료 조건을 분리한다. 명소를 수집해도 도로 셀 수와 분모 1,579개를 바꾸지 않는다.
- 공통 ExplorationSummary는 기존 도로 셀 요약 의미를 그대로 유지한다. 랜드마크는 담당 feature 내 LandmarkCollectionSummary를 프로필에 별도로 전달한다. XP나 점령 점수는 지급하지 않는다.

## 명소와 데이터

대상은 남양읍의 **성모마리아 기념상 1곳**이다. OpenStreetMap/Geofabrik 2026-11-08 배포판의 `node/13851756178`, version 1, 원본 명칭 성모마리아 및 historic=memorial / memorial=statue / statue=virgin을 사용했다. 좌표는 37.2046411, 126.8159948이며 실제 SGIS 남양읍 경계 안에 있음을 시험했다. 원본의 좌표를 주차장·차량 도착 지점으로 바꾸어 설명하지 않는다.

공개 지도 자료에서 선택한 시연용 1곳으로, 화성시 전체 관광지 목록이나 공식 인증 명소 목록이 아니다. 관광지 확장은 별도 선별이 필요하다. 이미지/설명문은 다른 사이트에서 복사하지 않았다. 출처·ODbL 고지·원본 부분집합·가공 도구는 [명소 데이터 고지](data/LANDMARK-DATA-NOTICE.md)에 보존했다.

자산 `namyang.landmarks`는 버전/지역 ID/명소별 ID·이름·좌표·반경·필요 시간·최대 공백·출처 URL을 가진다. 기본 수치 변경 시 데이터/정책 버전을 갱신해야 하며 기존 파일을 새 규칙으로 조용히 재해석하지 않는다. 재현 도구는 `tools/build_namyang_landmarks.py`이다. 이번 3차도 API 키·로그인 없이 확보한 공개 자료를 번들하므로 실행 중 네트워크가 필요 없다.

더 많은 관광지를 연결하려면 [한국관광공사 관광콘텐츠랩/TourAPI](https://api.visitkorea.or.kr/) 및 [공공데이터포털](https://www.data.go.kr/)에서 관광정보 API 활용 신청·서비스키 발급을 권장한다. 이번 구현에는 그 API를 호출하거나 발급하지 않았다.

## 체류 규칙

1. source가 저장소의 입력 출처와 일치하고 사용자/이벤트 ID/좌표/UTC 시각이 유효해야 한다. MOCK과 PLEOS 기록을 섞지 않는다.
2. 위치 정확도가 확인된 25m 이하이며, 정확도 원이 대상 지역 경계를 넘지 않아야 한다.
3. 명소 중심점과의 Haversine 거리 + 위치 정확도가 반경 100m 이하인 샘플만 체류에 사용한다.
4. 같은 사용자·명소에 대해 유효 샘플이 120초 동안 끊기지 않고 관측되어야 한다. 인접 샘플 시간 차가 15초를 초과하면 처음부터 다시 센다. 15초 정각은 허용한다.
5. 최소 유효 샘플 3개도 요구한다. 실제 120초/15초 설정에서는 더 많은 샘플이 필요하다. 한 번 들어온 좌표 뒤에 타이머를 돌리거나 시계를 2분 건너뛰어 완료하지 않는다.
6. 명소 반경/지역 이탈, 정확도 불량, 잘못된 위치는 미완료 체류를 끊는다. 중복/역행 시각과 최근 256개 내 중복 이벤트 ID는 시간 누적에 사용하지 않는다. 원래 시각을 유지한 더 오래된 재전송도 시각 워터마크로 거절한다.
7. 사용자/명소별 창을 분리한다. 겹치는 명소 범위는 각각 판정 가능하지만 현재 카탈로그는 1곳이다.
8. 이미 지역 도감이 열린 경우에만 명소 수집을 저장한다. 사용자+명소 최초 획득만 남기며 반복 방문해도 획득 수/최초 시각을 덮어쓰지 않는다.

이는 **명소 근처의 연속 위치 관측**이다. 실제 주차 상태·입장·문화재 방문·안전한 접근 가능성을 증명하지 않는다. 실차 상태 연동 없이 ‘주차 확인’으로 표시하지 않는다. 실제 사용에서는 위치 수집 권한/차량 상태/API 주기 검증이 별도로 필요하다. 운전 중 사용자에게 도감 조작이나 명소 방문을 유도하는 기능은 추가하지 않는다.

## 저장·복원

- `mock-landmarks.bin`에 획득한 사용자/명소 ID/최초 획득 UTC/source만 저장한다. 카탈로그/규칙 버전과 파일 형식을 검사한다.
- 미완료 체류 상태, 위치 원본, 경로, 앱이 꺼져 있던 시간은 저장/합산하지 않는다. 재시작 후에는 미완료 관측을 새로 시작한다. 획득한 카드는 복원한다.
- 임시 파일 쓰기·동기화·원자적 교체 후에만 획득 상태를 발표한다. 저장 실패 시 판정의 시각/후보/최근 이벤트 ID 상태를 되돌려 **동일한 마지막 입력**으로 재시도할 수 있다.
- 손상·버전 불일치·알 수 없는 명소 ID는 오류로 알리고 기존 파일을 지우지 않는다.
- 1차 발견 파일 및 2차 셀 파일은 형식/내용을 그대로 보존한다. 3개 파일 전체를 단일 트랜잭션으로 묶지는 않는다. 후순위 저장 실패 시 앞 단계의 유효 기록은 남을 수 있으며 재시도로 복구한다. 확장 시 Room 트랜잭션 통합을 권장한다.

## 화면 및 공유 사항

개인 탐험 지도에 명소 점(미수집 보라색/수집 금색)을 표시하고 도감 수, 최초 획득 시각, 미완료 최근 관측 시간을 보여준다. 프로필은 조회 요약만 받아 명소 도감 수/획득 내역을 표시한다. 내부 저장 파일을 화면이 직접 조회하지 않는다.

시연 버튼:

- 짧은 방문: 0·10·20초 명소 안 → 30초 밖, 획득하지 않아야 한다.
- 2분 모의 체류: 10초 간격 13개의 위치 이벤트를 0~120초 순서로 재생한다. 실제로 2분을 기다리는 동작이 아니며 화면에 모의 재생임을 표시한다.
- 이탈 후 복귀: 0~60초 안 → 70초 밖 → 80~140초 안, 두 번의 60초를 합쳐 획득하지 않아야 한다.

최초 획득 후 같은 시연을 다시 해도 중복 지급하지 않는다. 시연 시각은 저장된 도감/탐험 시각보다 이후로 정해 재시작 직후에도 시간이 역행하지 않게 한다.

공통 core 모델/인터페이스, route, Gradle, Manifest 및 최 담당 홈·점령 파일은 변경하지 않았다. MainActivity는 프로필에 담당 feature의 명소 요약을 전달하는 최소 연결만 변경했다. 새로운 전역 계약·DB·서버·SDK는 도입하지 않았다. 공동 계약 v0.1의 승인 대기 상태를 임의로 변경하지 않는다. 명소 요약을 다른 담당 기능이 소비하려면 추후 공통 계약을 별도로 합의해야 한다.

검증은 실제 공개 명소 좌표 위의 MOCK 입력이다. 실제 GPS·주차·차량 상태·백그라운드 수집·현장 접근성·서버·XP는 구현/검증 완료로 표시하지 않는다. UI의 획득 시각도 시연 이벤트의 UTC 시각에서 KST로 변환한 값이며 현장 방문 증거가 아니다.

3차 로컬 커밋: `남양읍 랜드마크 연속 체류 도감 수집 구현`. 사용자 검토 및 커밋 승인을 받았다. 실제 GPS 미연동의 MOCK 시연 범위를 유지한다. Push/PR/원격 병합은 수행하지 않는다.
