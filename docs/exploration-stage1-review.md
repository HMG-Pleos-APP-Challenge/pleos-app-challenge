## 1차 규칙과 완료 기준

대상은 경기도 화성시 남양읍 1곳이다. 위치가 실제 행정경계 안에 있는지 Polygon/MultiPolygon 및 내부 구멍을 포함해 판정한다. 정확도는 25m 이하이고 미확인·음수·NaN은 거절한다. 위치 오차 반경이 경계와 겹치는 샘플은 해금에 사용하지 않는다. 지역 안쪽에서 서로 다른 샘플이 3초 이상 간격으로 확인되고 최근 샘플 간격이 30초 이하이면 최초 발견한다. 이 값들은 담당 로직의 초기 제안이다. 연속 관측은 실제 연속 체류를 보장하지 않으며, 랜드마크의 체류 판정으로 재사용하지 않는다.

잘못된 좌표·정확도 불량·지역 이탈은 확인 중 상태를 끊는다. 중복 시각·역행 시각·동일 입력 재전송은 성공으로 세지 않는다. 사용자별로 판정 상태를 분리한다. 판정기의 임시 상태는 재시작 시 폐기하며, 이미 저장된 발견 시각보다 과거의 입력으로 새로운 발견을 만들지 않는다.

발견은 사용자+지역당 1개이며 최초 발견 시각을 덮어쓰지 않는다. 로컬 파일은 앱 전용 filesDir에 원자적으로 교체한다. 쓰기 실패 시 발견 결과를 발표하지 않고 같은 입력으로 재시도할 수 있다. 손상·버전 불일치는 사용자에게 오류를 표시하고 기존 파일을 유지한다. 위치 원본·미확정 위치·이동 경로를 장기 저장하지 않는다. MOCK 저장소는 실제 PLEOS 출처와 분리한다.

개인 지도는 실제 경계 윤곽 및 모의 진입점을 표시하는 프로토타입이다. 지도 SDK·배경 타일·실제 GPS 연동은 아니다. 최초 발견 후 지역 도감이 열리지만 전체 경계를 탐험 완료로 칠하거나 탐험률 100%로 표시하지 않는다. 2차 분모가 없으므로 탐험률은 ‘집계 없음’이다. 프로필은 동일 저장소가 제공한 Summary만 소비한다. XP는 기존 고정 미리보기이며 보상 경제를 임의 확정하지 않는다.

완료 기준: 정상 진입·범위 밖·정확도 불량·중복 재생·다른 사용자·재시작·저장 실패 시험, 단위 테스트·Lint·APK 빌드, Pleos 에뮬레이터 화면 동작 확인. 실제로 실행한 항목만 아래 검증 기록에 남긴다.

## 실제 데이터와 재현

- 원자료: 통계청 통계지리정보서비스(SGIS) 행정동 경계, 공공누리 제1유형.
- 가공·배포: [vuski/admdongkor](https://github.com/vuski/admdongkor), CC BY 4.0. 법정 경계 인증용이 아닌 프로토타입 행정동 경계로 사용한다.
- 파일: `ver20261001/HangJeongDong_ver20261001.geojson`.
- 원본 커밋: `3bc00489b76696db864bdbea4b19985cdfa8b403`.
- 선택 조건: `properties.adm_cd == "31241723"`; 이름 `경기도 화성시만세구 남양읍`.
- 데이터 ID `KR:SGIS:31241723`. SGIS 코드를 법정동 코드와 혼용하지 않는다. 데이터의 `adm_cd2=4159125600`은 별도 속성이다.
- 데이터 버전 `sgis-admdongkor-20261001`. 경계 좌표·순서·정밀도를 단순화하지 않고 텍스트로 변환했다. `.boundary`의 좌표는 GeoJSON과 같이 경도,위도 순서이다. 엔진 GeoPoint는 위도,경도 순서이다.
- 재현 도구: `python tools/extract_namyang_boundary.py --output <출력경로>`.
- 자산 SHA-256: `41d5766ab9392e06e5037c1a668d7d99c187aee5ec56ef38721ed38eddf9b1eb`.
- 첫 4행은 형식 버전/데이터 버전/지역 ID/지역 이름이다. 이후 POLYGON/RING/END_RING/END_POLYGON 사이에 경도,위도 쌍을 기록한다. 각 Polygon의 첫 Ring이 외곽이고 나머지는 내부 구멍이다.
- 데이터 라이선스 전문은 `docs/data/LICENSE-DATA.txt`에 보존한다. 이 경계는 API 키 없이 앱에 번들하므로 1차 실행에 로그인·인증키가 필요 없다.

출처 표기: 본 데이터는 통계청 통계지리정보서비스(SGIS, https://sgis.kostat.go.kr)에서 공공누리 제1유형으로 개방한 행정동 경계를 가공한 것이며(가공: vuski/admdongkor, https://github.com/vuski/admdongkor), CC BY 4.0으로 배포됩니다. 본 앱은 그중 남양읍 한 곳을 추출·텍스트 형식으로 변환했습니다.

## 2차 제안: 자동차 도로가 있는 셀만 해금

담당 선택안은 100m 지도 셀이다(크기는 도로 데이터와 GPS 검증 후 조정). 미리 차량 통행 가능한 도로 geometry와 남양읍 행정경계를 교차시켜 대상 셀 카탈로그를 만든다. 바다·산지·보행로만 있는 셀·사유지/통행금지 구간은 분모에서 제외한다. 실제 유효 주행과 교차한 대상 셀만 해금하고 인접한 모든 셀을 무조건 열지 않는다. 분모는 ‘버전이 고정된 대상 도로 셀 수’, 분자는 ‘개인이 해금한 대상 셀 수’로 동일 단위이다. 전체 국토 탐험률로 표현하지 않는다.

이 방식은 도로 세그먼트별 map matching보다 초기에 단순하다. 다만 도로가 있는 셀에 GPS만 찍혔다고 실제 운전을 입증할 수는 없으므로, 향후 차량 상태·이동 샘플 연속성·정확도·도로와 거리 조건이 필요하다. 점령 담당의 roadSegmentId와 셀 ID는 별개이며, 탐험 셀 수를 unlockedRoadCount로 잘못 보내지 않는다. 셀/도로 카탈로그 추가 및 Summary 연결 방법은 상대 공유 후 결정한다. 이번 1차에는 분모나 도로 데이터를 가짜로 만들지 않는다.

후보 자료: [국가교통정보센터 표준 노드·링크](https://www.its.go.kr/nodelink/nodelinkRef), [VWorld](https://www.vworld.kr), [SGIS 개발지원센터](https://sgis.kostat.go.kr/developer/html/home.html). 대상 자료의 도로 형상·차량 접근 속성·남양읍 범위·갱신 기준을 다운로드 후 검사해야 한다. VWorld/SGIS API를 쓰기로 하면 사용자가 로그인해 해당 서비스 인증키를 발급해야 한다. 도로선 이름/목록만으로 도로가 있는 셀 분모를 만들 수 없다. 회의의 [서울 도로노선 정보](https://data.seoul.go.kr/dataList/OA-22650/S/1/datasetView.do)는 도로노선 속성 자료이므로 geometry 포함 여부를 추가 확인해야 한다. 남양읍 경계는 확보됐으므로 현재 서울 전환은 불필요하다.

## 3차 제안: 랜드마크 체류 도감

지역/셀 발견과 별개이다. 셀은 방문 공간을 기록하고 랜드마크는 명소 반경 내 연속 관측 조건으로 카드/도감 항목을 획득한다. 같은 위치 샘플이 두 판정을 동시에 만족할 수 있으나 저장 키와 완료 조건을 분리한다. 체류 시간은 아직 합의되지 않았으므로 임의로 1분/5분으로 확정하지 않는다. 경계 밖 이탈·정확도 불량·장시간 샘플 누락·재시작 시 체류 누적을 어떻게 끊을지도 정해야 한다. 최종 회의록에서는 후속(P2)이지만 사용자가 요청한 3차 작업으로 추후 별도 구현·검토한다.

랜드마크 후보: [한국관광공사 TourAPI](https://api.visitkorea.or.kr). 채택 시 공공데이터포털에서 관련 관광정보 API 활용 신청·서비스키 발급을 제안한다. 명소 중심점만으로 차량 주차 가능 여부를 단정하지 않고 안전한 접근 지점/허용 반경을 별도로 확인한다.

## DB 추천과 팀 공유

전체 서비스 추천은 앱 로컬 Room(SQLite) + 서버 필요 시 PostgreSQL/PostGIS이다. Room은 발견/해금/XP 중복키와 트랜잭션·마이그레이션에 적합하고 PostGIS는 지역 경계·도로·랜드마크의 공간 질의에 적합하다. 서버 점령 집계·동기화가 실제로 필요해지기 전까지 서버를 MVP 필수로 만들지 않는다. Room과 서버는 현재 도입하지 않았다. 현재 파일 저장소는 단일 프로세스·작은 지역 발견 목록을 위한 임시 구현이며, 셀 수 증가와 XP 원장에는 DB 전환을 권장한다.

권장 테이블은 region_catalog(공급자/버전/코드/부모/경계), exploration_unit_catalog(버전/셀ID/통행가능성), user_region_discovery(userId/regionId 최초발견), user_unit_unlock(userId/unitId 최초해금), landmark_catalog(위치/판정규칙), user_landmark_unlock, xp_award(고유 awardId), sync_outbox 이다. 사용자별 unique 키·UTC timestamp·데이터 버전·이벤트 출처를 유지한다. 다른 게임이 내부 테이블을 직접 읽지 않고 기존 Summary/Repository를 소비해야 한다.

공통 보호 파일(core/navigation/Gradle/Manifest)은 변경하지 않았다. MainActivity는 탐험 저장소를 단일 인스턴스로 연결하고 화면/프로필에 같은 Summary를 전달하는 최소 연결 변경이다. 기존 최 담당 홈·점령 파일을 수정하지 않았다. 홈의 기존 가상 경로 버튼은 점령 fixture를 유지한다. 그 경로의 가상 지역 ID를 실제 남양읍 해금에 섞지 않는다. 남양읍 탐험은 개인 탐험 화면의 전용 모의 위치 버튼으로 확인한다. 공통 LocationSource가 확정되면 해당 단일 입력 스트림에서 LocalExplorationFeature.onLocation으로 배포하며 기능에서 별도로 SDK를 구독하지 않는다.

## 검토 요청과 커밋 후보

커밋 후보: `남양읍 최초 발견 판정과 개인 도감 저장 구현`. 실행 로직 변경이므로 `(로직변경x)` 접두어를 쓰지 않는다. 사용자 승인 후 로컬 커밋만 수행한다. Push/PR/main 병합은 요청 전 수행하지 않는다. 1차 검토 후 2차 기능을 진행해 기능별 커밋 경계를 유지한다.
