## 개발자 실행
저장소 루트에서 PowerShell 7로 실행한다.
```powershell
pwsh -File docs/exploration-spec/Run-ExplorationSimulation.ps1
```
실제 Android 프로젝트의 JVM 테스트에 준비된 위치·시간·복구 입력을 주입한다. 실행 결과는 app/build/reports/exploration-simulation.csv, 개별 테스트 상세는 app/build/reports/tests/testDebugUnitTest/index.html에 남는다. 자동 판정 통과는 해당 행에 연결한 테스트 메서드의 범위를 뜻한다. 같은 행의 화면 조건과 실제 장치 조건은 별도로 확인한다. 테스트 실패 시 Gradle HTML 보고서에서 실패 메서드와 기대값·실제값을 확인한다.

## 장치에서 확인할 항목
1. 디버그 빌드에서 개발자 도구의 모의 기록을 선택한다. 빈 시험 사용자로 경계 밖·불량 정확도·정상 진입 순으로 재생하고 발견 수 0 → 0 → 1을 확인한다.
2. 도로 이동을 두 번 재생한다. 처음 방문한 4개 구역만 색이 바뀌고 두 번째 재생은 개수와 XP를 유지해야 한다.
3. 짧은 체류 → 이탈 후 복귀 → 2분 연속 체류 순으로 재생한다. 마지막 시나리오에서만 명소 카드를 얻고 도로 탐험률은 유지돼야 한다.
4. SDK와 서버는 모의 기록과 분리된 사용자로 검증한다. 연결을 끊고 경로를 주입한 뒤 기기 기록을 확인하고, 재연결·재시작 뒤 같은 구역 ID가 확정되는지 비교한다. 서버 설정이 없으면 로컬 모드로 기록하고 서버 항목은 미검증 처리한다.
5. Pleos 장치에서 앱을 홈으로 전환한 후 SDK 경로를 입력한다. 서비스 생존 외에 저장된 구역 ID와 재실행 결과를 대조한다. 지원 실차에서는 운행 중 화면 제한과 신호 복귀를 별도로 확인한다.
6. 각 수동 결과에는 요구사항 ID, 커밋, 장치·입력 출처, 기대값, 실제값, 실행시각, 화면 또는 로그를 남긴다. 계정 복원은 시험 이메일과 두 설치가 필요하다. 익명 세션 토큰이나 비밀번호는 증적에 포함하지 않는다.

## 노션 등록
지정 보관함에서 requirements.csv를 데이터베이스로 가져온다. 요구사항 열을 제목으로 사용한다. ID로 자동 검증 결과와 연결하고, 구현 상태가 보완 필요인 행과 수동 검증 행을 각각 필터링한다.
