# 방향별 도로 점령 서버 연결 설계 제안

작성 기준은 통합 커밋 35e576a다. 상태는 검토용 제안이다. 개인 게임 규칙은 사용자 확정 사항이며, 신규 인증 경계·RPC·DB·운영 정책은 공동 확인 대상이다. 2026-11-11 Notion 연결 조회에서도 계약 v0.1은 공동 승인 대기로 반환됐다. 원격 DB 적용 전 계약 변경 범위와 양측 담당을 확인한다.

## 목적과 완료 기준

같은 방향 도로를 통과한 여러 계정의 인정 기여를 서버에서 합산하고, 매일 KST 낮 12시의 직전 36시간 결과를 모든 기기에 동일하게 제공한다. 한 계정이 여러 기기에서 전송해도 방향·반일당 1회만 인정한다. 홈·프로필은 기존 ConquestSummary 형식으로 서버 확정 값을 받는다.

완료 기준은 두 계정·두 기기의 기여 합산, 응답 유실 후 재전송 멱등성, 서버 시간 경계와 동점·무기여 처리, 프로세스 종료 후 큐 복구, 출처별 기록 격리, 타 계정 요청 거부, 카탈로그 버전 불일치 시 기존 데이터 보존이다. 실제 주행 증명과 실차 정확도는 별도 검증 항목이다.

## 계정과 팀 정책

제안하는 서버 소유 키는 JWT에서 확인한 Auth UUID다. 설치 ID는 로컬 기록 찾기에 사용한다. 요청 본문에서 다른 계정의 userId를 지정할 수 없게 한다. 큐는 설치 ID·Auth UUID·출처·도로 버전에 묶고, 다른 계정으로 로그인하면 이전 큐 전송을 보류한다.

팀 목록은 서버 데이터로 제공하고 현재 시연은 2팀을 등록한다. 서버의 팀 선택은 계정·출처별 최초 선택을 원자적으로 확정한다. 같은 팀 재요청은 성공하고 다른 팀은 거부한다. 여러 기기가 동시에 다른 팀을 선택해도 하나만 확정된다. 기여에는 인정 당시 팀을 보존한다.

기존 u-demo-01 및 로컬 MOCK 기록은 시연 자료로 보관하는 방안을 제안한다. 기존 로컬 PLEOS 기록도 검증 근거 없이 서버 확정 기여로 승격하지 않는다. 기존 파일을 읽는 경로와 새 서버 캐시를 분리해 롤백 시 원본을 복구할 수 있게 한다. 계정 복원 제한 완화는 미전송 큐와 소유 계정 매핑이 갖춰진 뒤 검토한다.

## 서버 검증과 전송 순서

앱이 전송한 RoadVisited 하나만으로 실제 완주를 서버가 재검증할 수 없다. 서버 검증을 위해 해당 통과의 입구부터 출구 진출까지 필요한 좌표·UTC 시각·정확도 근거를 함께 보내는 방안을 제안한다. 서버 판정은 기존 DirectedRoadDetector의 중간 시작·U턴·이탈·긴 끊김·점프·정확도 조건과 동일한 픽스처로 비교한다. 클라이언트 위치만으로 물리적 주행의 진위를 보증할 수는 없다.

영속 큐에는 탐지 완료 이벤트와 검증 근거를 같은 트랜잭션 또는 원자적 파일 기록으로 남긴다. 기록 성공 이후 전송 대상으로 공개한다. 근거 수집 중 앱 종료는 미완주로 처리하고, 완료 탐지와 큐 기록 사이 저장 실패는 오류로 표시한다. 저장 불가 상황까지 무손실이라고 안내하지 않는다.

서버는 계정·출처·카탈로그를 확인한 뒤 이벤트 키 및 내용 일치 여부를 검사한다. 이미 처리한 동일 이벤트는 원래 결과를 반환한다. 새 이벤트는 팀·시간·완주 근거·방향별 반일 중복을 검사하고 처리 결과와 인정 기여를 원자적으로 기록한다. 서로 다른 이벤트 ID로 같은 반일에 재전송해도 합산하지 않는다.

앱은 항목별 결과, 계정, 출처, 버전을 확인한 뒤 응답에 포함된 전송 항목만 ACK한다. 새로 쌓인 행은 유지한다. 연결 실패와 결과 미확인은 재시도하고, 지연·잘못된 근거 등 최종 거부는 사유를 남겨 재시도를 종료한다. 큐 가득 참은 기존 미전송 항목을 보존하고 오류로 알린다. 행 수·배치 크기·근거 보관 기간은 실측 후 정하는 기술 항목이다. 위치 근거의 서버 보관 기간은 수집 전 공동 확인한다.

RPC 책임은 팀 선택, 기여 제출, 점령 스냅샷 조회로 나눈다. 스냅샷은 팀 목록·본인 소속·본인 누적 기여·방향별 소유팀·마지막 완료 정산·서버 시각·버전·revision을 포함하도록 제안한다. 전역 도로 소유팀과 개인별 기여 읽기 권한을 구별하며, 다른 사용자의 이동 근거를 클라이언트에 반환하지 않는다. 관리자 키는 앱에 넣지 않는다.

## 지연 입력과 정산 제안

기존 개인 확정 규칙을 서버에서도 유지하는 방안을 우선 제안한다. 신규 기여의 통과 시각이 서버 수신 시점의 최근 KST 낮 12시보다 이전이면 거부한다. 예를 들어 11:59 통과가 12:01 처음 수신되면 지연 거부다. 이미 서버가 인정한 이벤트의 응답 유실 재전송은 기존 결과를 반환한다. 탐험의 30일 오프라인 허용과 사용자 설명을 구별해야 한다. 이 선택은 서버 구현 전 사용자·상대 개발자 확인 대상이다.

서버 정산 T는 UTC로 저장하고 KST의 매일 12시로 정의한다. 기여 창은 [T-36h,T), 12시 정각 기여는 다음 정산에 포함한다. 사용자·방향·KST 날짜·반일당 1점, 단독 최다 팀 점령, 동점 시 기존 소유팀이 공동 1위면 유지하고 그 외 중립, 무기여 중립이다. 팀 수를 두 개로 고정하는 분기를 두지 않는다.

서버의 같은 출처·정산 기준을 직렬화해 기여 수신과 정산의 경쟁을 처리한다. 수신 트랜잭션이 인정한 기여 집합과 정산 컷오프가 일관돼야 한다. 첫 운영 기준 시각과 초기 중립 상태를 기록하고 누락 정산은 시간순 복구한다. 정산 revision과 완료 상태를 원자적으로 공개하며 재실행은 같은 결과를 낸다. 클라이언트가 과거 정산 시각을 골라 변경하는 API를 제공하지 않는다.

정시 실행 담당과 실패 알림·누락 복구 운영은 공동 확인 대상이다. 일정 작업이 늦으면 화면에는 마지막 완료 정산 시각을 표시한다. 서버 확정 점령과 로컬 모의 결과가 같은 화면에서 덮어쓰이지 않도록 출처를 표시한다. 점령 XP 추가 지급은 별도 요구사항이 있을 때 검토한다.

## 구현 순서와 검증

1. 점령 내부 영속 큐부터 구현한다. 중복, 저장 실패, 재시작, 일부 ACK, 계정·출처·버전 격리 테스트를 작성한다. 친구의 큐를 변경하지 않는다.
2. 인증 호출 경계·계정 매핑 및 요청/응답 계약을 공동 검토한다. 기존 탐험 로그인·동기화·복원 회귀를 확인한다.
3. 로컬 격리 DB에 카탈로그·팀 선택·기여 검증·정산을 구현한다. 2계정 합산, 3팀 동률, 반일 중복, 자정·12시·36시간 경계, 응답 유실, 병렬 기여/정산, 권한 거부를 검증한다.
4. 점령 세션의 큐·서버 스냅샷을 연결한다. 홈/프로필은 기존 요약을 받고 대기·서버 오류는 점령 화면에서 표시한다.
5. 검증된 마이그레이션과 복구 절차를 준비하고 합의한 원격 환경에 적용한다. MOCK은 업로드를 차단하며 에뮬레이터와 차량을 분리한다.

## 다음 확인이 필요한 결정

- 지연 전송은 위의 마감 이후 거부 정책을 유지할지 결정한다. 변경 시 재정산과 서버 보관 범위도 함께 설계한다.
- 인증 RPC 호출부의 공용화 범위, 상대 인증 담당자와의 연결 방법을 확인한다.
- 정시 정산 운영 담당, 기존 로컬 기록 취급, 위치 검증 근거 보관 정책을 확인한다.

이번 산출물은 설계 문서다. 실행 코드·원격 DB 변경 및 신규 API 적용은 후속 구현 항목이다.
