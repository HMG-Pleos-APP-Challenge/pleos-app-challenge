# 탐험·점령 통합 검증
- 탐험 기준 e90c987, choi 기준 c31db41, main 기준 35e576a.
- MainActivity.kt의 주행 중 화면 게이트와 프로필·설정 연결에서 충돌했다. choi의 점령 재로딩·복원 제한·통합 시연을 유지하고 탐험의 자동 기록·도감 잠금·권한 복구를 연결했다.
- ExplorationTrackingService.kt의 오류 상태와 위치 전달부에서 충돌했다. choi의 기능별 독립 로딩·오류 전달 구조를 적용하고 탐험의 재구독·연속 기록을 유지했다.
- 공유 위치는 탐험과 점령에 전달한다. 탐험만 시작하면서 점령 전달이 기본적으로 차단되던 로컬 조정을 해제했다. 점령의 차량 상태 조건은 점령 입력에 적용한다.
- feature/conquest 및 feature/home는 origin/choi와 동일하다.
- Android 단위 테스트 172개 통과. 확장 도로·지역별 경로·기여 저장·정산·동점·만료·이관 회귀를 포함한다.
- 도로 데이터 도구 테스트 14개 통과. Shapely 2.1.2와 osmium 4.3.0은 저장소 외부의 격리된 검증 경로에서 사용했다.
- 탐험 요구사항 21개 연결 판정, 장치 도감·보상·오프라인 확정·모의 계정 복원, 백그라운드 SDK·4셀·TTS·재로딩 통과.
- 통합 APK의 IntegrationSmokeProbe 통과. SDK/mock 격리, 완주 및 정산, 중도 이탈·U턴 거부, 저장 기록 보존을 확인했다.
- 사용자 화면 전체의 시각적 회귀와 실제 이메일·실차는 별도 검증 대상이다.

## 반영한 탐험 기능

- 위치 권한을 허용하면 foreground service가 화면과 독립적으로 탐험을 기록한다. 화면·설정·알림의 기록 중지 조작을 제거하고 SDK 연결 재시도를 추가했다.
- 탐험률은 서버 설정 시 확정 기록을 사용한다. 지도·목록·상세는 동기화 대기 구역을 별도로 표시하며 대기 구역에는 사선, 확정 구역에는 점을 사용한다.
- 지역 최초 발견 전에는 지역 윤곽과 방문 안내를 제공한다. 최초 발견 후 구역·명소 도감을 열며 기기에서 발견한 기록으로도 공개 상태를 판단한다.
- 전체 획득 구역에 접근하도록 30개 목록 제한을 해제하고 좁은 화면의 범례를 세로로 배치했다.
- 새 설치에서는 새 탐험 시작 또는 기존 계정 복원을 선택한 뒤 자동 기록을 시작한다. 선택 대기를 설치 ID 생성 전에 저장해 프로세스 재시작으로 선택이 우회되지 않도록 했다.
- 권한·차량 위치 설정 진입과 설정 복귀 시 기록 재연결을 추가했다. 위치 신호가 30초 이상 없으면 신호 대기를 표시한다.
- 요구사항 21개를 문서화하고 JVM·Android 장치·SDK 시뮬레이션 실행 도구를 추가했다. 결과에는 커밋, 미커밋 변경 여부, 항목별 결과와 검증 범위를 남긴다.

## 반영한 choi 변경과 충돌 해결

- 남양읍 확장 도로 카탈로그, 기존 기록·미처리 방문 이관, 방향별 기여와 정산·동점·만료 처리를 반영했다.
- 도로 검색·필터·지도 표시 범위, 홈의 점령 상태·오류 재로딩, 탐험·점령을 함께 재생하는 메모리 시연을 반영했다.
- MainActivity.kt에서는 choi의 점령 가용성·오류 재시도·계정 복원 제한·통합 시연을 탐험의 도감 잠금·자동 기록·설정 UI와 연결했다.
- ExplorationTrackingService.kt에서는 choi의 기능별 독립 로딩과 실패 격리를 적용했다. 한 기능의 기록 실패가 다른 기능에 대한 동일 위치 전달을 막지 않게 했다.
- 앱이 시작한 공유 위치 수집에서 점령 전달을 기본 차단하던 탐험 브랜치의 조정을 해제했다. 점령의 기존 차량 상태 판정은 점령 소비자에 적용한다.
- 점령·홈 전용 소스는 c31db41의 파일 내용과 같음을 비교했다. 공통 모델·route·namespace의 구조 변경은 없다.
