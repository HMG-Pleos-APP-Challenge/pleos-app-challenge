# 사용자 ID·경험치·레벨·프로필

2026-11-09 · 사용자 2번 커밋 요청에 따라 구현·검증 후 로컬 커밋

## 사용자와 기존 기록

처음 실행할 때 `identity/installation-user.txt`에 u-UUID를 원자 저장한다. 앱 프로세스 재시작과 업데이트 후 같은 앱 데이터가 유지되는 동안 같은 ID를 사용한다. 로그인/서버 계정·기기간 동기화는 아니다. 앱 삭제·데이터 삭제 시 로컬 ID와 기록은 초기화된다. 파일이 손상되면 새 ID를 몰래 생성하지 않고 파일 확인 오류를 표시한다.

ID를 먼저 저장한 다음, 기능 세션을 열기 전에 기존 u-demo-01의 지역·셀·명소 기록을 새 ID로 연결한다. mock / pleos-emulator / pleos 세 저장 공간을 모두 처리한다. 각 파일을 기존 버전 검사와 원자 교체로 갱신하며, 중간 실패 시 같은 UUID로 다음 실행에서 남은 파일을 재시도한다. 이미 바뀐 파일은 다시 쓰지 않는다. 다른 사용자 기록은 유지하고 같은 사용자·같은 대상이 중복되면 최초 획득 기록을 유지한다. ID 이관 중 오류가 있으면 임의의 새 계정으로 진입하지 않는다.

## 개발용 경험치 규칙 v1

| 최초 획득 | XP |
|---|---:|
| 지역 발견 | 100 |
| 도로 셀 해금 | 10 |
| 랜드마크 도감 | 200 |

레벨은 1에서 시작하고 100 XP마다 1씩 오른다. 예: 99 XP는 레벨1, 100 XP는 레벨2, 340 XP는 레벨4·다음 레벨까지60 XP다. 보상과 레벨 곡선은 현재 개발용 규칙이며 팀 공통 최종 밸런스 승인을 의미하지 않는다. 도로 점령 담당 기능의 XP는 임의로 지급하지 않았다.

`FileProgressRepository`가 기존 공통 ProgressRepository/awardOnce/UserProgress/XpAward 계약을 구현한다. 공통 모델 필드·인터페이스·route는 변경하지 않았다. 사용자/지급 ID/금액/원인 이벤트를 저장하며 동일 ID 재요청은 추가 지급하지 않는다. 같은 ID에 다른 내용이 오면 충돌로 처리한다. 유효하지 않은 지급·음수·합계 오버플로는 저장 전에 거부한다. 파일별 Mutex는 여러 repository 인스턴스가 같은 파일을 사용할 때도 공유하며, 매 작업 최신 파일을 읽는다. 앱은 기본 단일 프로세스를 사용한다.

`progress/mock-xp.bin`, `progress/pleos-emulator-xp.bin`, `progress/pleos-xp.bin`으로 경험치도 분리한다. 모의/에뮬레이터 XP를 실차 XP로 합치지 않는다. 원장은 버전이 있는 바이너리·fsync·동일 폴더 원자 교체를 사용한다. 신규 DB/서버/의존성은 추가하지 않았다.

## 탐험 저장과 경험치 복구

이미 저장된 지역·셀·도감을 보상의 기준으로 삼는다. 시작할 때 기존 획득분의 지급 ID를 재구성해 원장과 대조하고, 새 해금이 생기면 한 번의 배치로 누락 보상을 지급한다. 반복 위치·중복 재생·재시작으로 XP가 늘지 않는다. 탐험 저장 직후 프로세스가 종료되거나 XP 저장이 실패해도 다음 세션 시작 시 저장된 획득분을 기준으로 다시 맞춘다. 탐험 파일과 XP 파일을 하나의 트랜잭션이라고 주장하지 않는다. 오류 시 기존 파일은 보존하며 저장 문제가 해결돼야 복구할 수 있다.

모든 GPS 수신마다 원장을 읽고 쓰지 않는다. 신규 획득 또는 초기 복원 때만 보상을 재계산하고 batch award를 수행한다. 단순 위치 수신에는 현재 progress 값을 유지한다. 기존 보상의 복원은 TTS 신규 해금 알림을 만들지 않는다.

## 프로필과 공유 범위

MainActivity의 고정 u-demo-01을 제거하고 ID 준비·기록 이관이 끝난 후 기능을 연다. 프로필에는 선택한 모의/SDK 세션의 UserProgress를 전달한다. 화면은 내부 저장 파일을 직접 읽지 않고 누적 XP·레벨·다음 레벨까지 남은 XP를 표시한다. 백그라운드 서비스 세션도 같은 보상·progress 갱신 경로를 사용한다.

공통 보호 영역에는 core/data/FileProgressRepository 구현을 추가했다. 상대 담당자는 기존 ProgressRepository 계약으로 원장을 사용할 수 있지만 출처별 파일·지급 ID 네임스페이스·레벨 규칙을 공유해야 한다. 이 구현을 공동 계약 v0.1의 승인 완료로 표시하지 않는다. 공통 모델·인터페이스·namespace·route는 그대로다. 원격 push/PR/병합 없음.

## 검증

- 총 78개 단위 테스트 통과, Lint 오류0·기존 경고5, 앱/진단 APK 빌드 성공.
- 설치 ID의 동시 생성·재사용·손상 시 보존, XP 중복·동시 지급·레벨 경계·원장 재로딩·충돌/음수/오버플로/저장 실패/손상 거부 검증.
- 세 출처의 기존 기록 이관, 이관 재실행 시 파일 불변, 중간 파일 실패 후 재시도, 기존 획득분의 중복 없는 보상과 출처 분리 검증.
- 실제 Pleos 에뮬레이터에서 IdentityProgressProbe를 프로세스를 달리해 두 번 실행: 기존 지역1·도로 셀4·명소1 보존, 340 XP·레벨4 복원, 동일 UUID와 중복 없는 지급 확인.
- 백그라운드 서비스 기기 재검증: 합성 위치의 실제 SDK 콜백으로 지역1·셀4에 140 XP 지급, 레벨2 복원, ON_DEVICE TTS 재생 완료, 명시적 중지 확인.
- 기기 검증은 `SdkUnlockProbe -e mode identity` 또는 기존 `-e mode background` 사용. background는 에뮬레이터 확인과 syntheticEmulator=true·위치 권한·일시적 mock-location AppOp가 필요하고 종료 후 원복한다. identity 검증은 실제 앱 데이터를 새 ID로 이관하므로 읽기 전용 검사가 아니다.
- 기기에서 검증한 것은 저장·요약 전달 경로다. 마지막 UI의 시각적 검사는 기존 창 캡처 도구 오류로 별도 완료 표기하지 않는다.
