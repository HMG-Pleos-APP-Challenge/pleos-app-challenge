# 도로 점령 기반 로직

공통 계약 v0.1은 공동 승인 대기다. 기존 공통 모델/인터페이스를 변경하지 않고
`feature/conquest` 내부에 사용자 확정 게임 규칙을 구현했다.

## 기능

- `ConquestTime`: KST 오전/오후, 매일 12시 정산, 직전 36시간 [시작,종료) 계산.
- `ContributionLedger`: 팀 선택 후 변경 금지, 미선택/선택 이전 기록 제외,
  사용자·방향 구간·반일당 1회 기여, 이벤트 재전송 방지, 입력 출처 분리.
- `ConquestSettlement`: 단독 1위 소유, 기존 소유팀이 공동 1위면 유지,
  그 밖의 동점/무기여는 중립. 누락된 정산을 순차 계산.
- `FileConquestStore`: 점령 전용 버전 파일을 임시 파일에 쓰고 동기화 후 원자 교체.
  손상/버전 불일치 시 자동 초기화하지 않는다.
- `LocalConquestFeature`: 기존 ConquestFeature 구현. 기록 저장 성공 후 상태 반영,
  재시작 시 기여·팀·정산 복구. 조회 시 도래한 정산 반영.

## 연결 조건

남양읍 카탈로그·완주 판정·지도/홈 연결은 `conquest-namyang.md`에 정리했다.
MainActivity에서는 점령 세션만 교체하고 기존 탐험·프로필 내부는 유지했다. 실제 위치 SDK는 아직 연결하지 않았다.
앱 조립부에는 데이터 버전, 방향별 구간 ID 목록, 팀 ID 목록,
입력 출처, 점령 전용 저장 파일과 UTC 시계를 주입한다. 생성과 호출은 파일 I/O가
있으므로 UI 스레드 밖에서 수행하며, 파일 하나당 앱에서 인스턴스 하나를 관리한다.

`RoadVisited`는 완전한 통과 판정이 끝난 이벤트만 전달한다. 이 구현은 좌표로
도로 완주를 판정하지 않는다. 방향을 포함하는 roadSegmentId는 점령 카탈로그에서
정의하며 탐험의 100m 셀 ID를 그대로 사용하지 않는다. 새 공통 필드는 추가하지 않는다.

MOCK과 PLEOS는 서로 다른 파일을 사용한다. 탐험 저장 파일은 사용하지 않는다.
기여는 1점이며 팀 수는 고정하지 않는다. 누적 기여 수는 즉시 갱신하고 소유권은
정산 시에만 변경한다. ownedRoadCount는 방향별 소유 구간 수다.

## 지연·복구 정책

신규 입력 시 수신 시각보다 미래인 기록과 수신 시점의 최근 KST 12시보다 오래된
기록은 거부한다. 마감 결과를 소급 변경하거나 다음 창에 늦게 끼워 넣지 않는다.
이미 저장된 인정 기여는 복구 시 거부하지 않고 각 정산 창에 다시 집계한다.
이것은 오프라인 기록 업로드를 지원하는 정책이 아니다.

파일에는 초기 기준 시각·마지막 기록 시각·팀 선택·인정 기여를 보존한다.
소유 상태는 정산을 시간순으로 재실행해 복구한다. 현재 MVP는 전체 기록을 읽고
재계산하므로 기록량이 커지면 호환되는 체크포인트/보관 정책이 필요하다.
카탈로그/팀 목록을 바꿔 기존 ID가 사라지면 명시적 마이그레이션이 필요하다.

## 검증

JDK 17, SDK 34에서 저장소의 기존 명령을 사용한다:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Windows 한글 경로의 AGP 검사에 막히면 해당 실행에만
`'-Pandroid.overridePathCheck=true'`를 추가한다. 공통 Gradle 설정은 변경하지 않았다.

전용 테스트는 `app/src/test/java/com/daehyundai/map/feature/conquest`에 있다.
실제 지도/방향 데이터 검증, GPS 완주 판정, Android 파일 시스템에서의 원자 교체,
화면 연결과 Pleos Emulator 시연은 별도 검증 대상이다.
